# Guion de demostración y entrega

Documento de preparación; todos los pasos requieren ensayo. Objetivo: que los tres integrantes expliquen el comportamiento y las limitaciones, no solo reproduzcan un vídeo.

## Preparación

- Identificar commit de firmware/apps y versiones de SO.
- Placa y periféricos comprobados, dos Android reales y Windows disponibles.
- Red local probada; alternativa por router si falla el hotspot.
- Credenciales configuradas sin mostrarlas al público; límite de API conocido y datos de demostración no sensibles.
- Evidencias de pruebas largas —cinco minutos sin red y 30 min bloqueado— preparadas con fecha y condiciones.
- Cada integrante sabe iniciar, detener y recuperar la demo.

## Recorrido principal

1. **Solo placa:** mostrar cara, contacto, ruido, sonido breve y temporizador. Explicar que el INMP441 no transcribe voz.
2. **Android:** acceso local, conexión, telemetría y cambio de umbral con confirmación física. Iniciar una sesión y consultar el estado confirmado.
3. **Texto y voz:** solicitar una tarea acotada y comprobar que utiliza las mismas herramientas. Si una limitación fue acordada, explicarla antes de mostrar el recorrido alternativo.
4. **Windows presente:** abrir la app y observar el cambio de centro, manteniendo la sesión. Mostrar solicitud desde acompañante y una captura delegada si forma parte de la matriz validada.
5. **Agentes:** provocar un fin de turno o solicitud de permiso de Claude Code. Explicar que la mascota informa y no aprueba ni garantiza el trabajo.
6. **Micrófono:** repetir las combinaciones reales de llamada/voz ensayadas y mostrar el uso de texto cuando no procede capturar.
7. **Salida de Windows:** simular suspensión/desconexión; Android recupera el control. Mostrar que un relevo abrupto pausa nuevas llamadas pagadas hasta conciliar gasto.
8. **Sin internet:** mantener estudio, personaje y control local. La IA informa indisponibilidad sin bloquear la interfaz.
9. **Reconexión:** mostrar evidencia y, cuando el tiempo lo permita, ejecutar el corte local y recuperación sin duplicados.
10. **Cierre:** revisar historial, borrado y límites. Cada integrante explica una decisión fuera de su área principal.

## Artefactos previstos

- Repositorio con instrucciones reproducibles y versiones fijadas.
- APK, aplicación Windows y firmware identificados; instrucciones de instalación.
- Informe del sistema y decisiones posteriores a la v3.
- Diagrama de conexiones verificado y fotografías del montaje.
- Matriz P01–P19/A01–A04 con resultados y evidencias.
- Relación con la rúbrica original, limitaciones y acuerdos docentes.
- Atribuciones/licencias de recursos y dependencias.

No se publica código con credenciales, bases de datos personales o material académico restringido. Las herramientas de diagnóstico de voz no forman parte de la interfaz final.
